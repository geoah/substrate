# Codex Astra's UI/UX review of the first build (2026-10-31)

On 2026-10-31 the owner asked "have you done any reviews of the ui and ux with codex
astra?". This is that review: Codex (gpt-6-astra) read the first build's screenshots, the
13 Hevy screenshots the owner attached as inspiration, and the Spotter source, and
reported back the same morning. It reviewed the Table layout, which was then the only
one ([design/table.md](../design/table.md)).

What follows is the review as delivered, verbatim. Its links pointed at files on the
build Mac (the screenshots under `/tmp/spotter-shots/`, the Spotter sources in the
rxtx.dev worktree, the owner's attachments); they are kept as plain text. Spotter's
`SpotterKit` became `WorkoutsKit` in this repository.

## The review

Spotter has a solid session layout, but **starting from a preview, reading suggested values, and trusting the Finish summary need fixes before gym use**.

I reviewed the supplied Spotter captures, all 13 Hevy references, and the implementation. No files or workout data changed. Live testing was blocked by `DEVICE_IN_USE`, including after the suggested bounded wait. Findings below distinguish screenshot evidence from code inspection; notification delivery, VoiceOver operation, and Health export uniqueness remain unverified.

No app-wide blocker established.

1. **Major — Routine preview: Start is obscured by the tab bar.**  
   **Evidence:** `02-preview-bug.png` shows “Start routine” directly behind the tabs. `RoutinePreview.swift:20` installs a bottom toolbar without hiding the tab bar.  
   **Gym impact:** After checking the routine, the primary action is visually obstructed and competes with navigation. Starting from the routines list provides an alternative, so this is not an app-wide blocker.  
   **Smallest fix:** In `RoutinePreview.swift`, hide the tab bar on this pushed screen so the existing system bottom toolbar has its own space. Keep the Back button.

2. **Major — Session grid: suggested loads and reps look disabled.**  
   **Evidence:** In `03-session.png`, suggested `105` and `10` are substantially fainter than previous values. In `19-dark.png`, even the enabled Single Leg RDL `1L` values are barely visible. `SetRow.swift:184` renders suggestions as `TextField` prompts.  
   **Gym impact:** The numbers needed to select weights are the least legible information. A lifter must bring the phone closer or open the field to distinguish a usable suggestion from a locked row. Hevy’s reference ghosts are visibly stronger.  
   **Smallest fix:** In `SetRow.swift`, render empty-field suggestions with an explicitly styled overlay instead of relying on placeholder rendering. Use an adaptive, readable foreground; retain regular versus bold weight and the completed-row tint to distinguish suggested from logged values.

3. **Major — Finish: the summary does not reflect “Mark them done as shown.”**  
   **Evidence:** `FinishSheet.swift:27` requests the same summary regardless of `markDone`. `Finish.swift:67` counts only performed rows; the pending-set decision is applied later during saving. The supplied captures show **1 working set / 1,050 kg** in `Finish`, versus **14 sets / 6,973 kg** in `saved history`.  
   **Gym impact:** The confirmation screen cannot reliably tell the lifter what will enter history and influence future suggestions. Additionally, `markDone` silently omits pending rows without complete values.  
   **Smallest fix:** Have `FinishSheet.swift` request a projected summary using the selected pending-set policy. Show how many sets will be added and how many cannot be completed. Preview and save should use the same projection.

4. **Major — RPE entry: precision targets and hidden rest controls slow the between-set loop.**  
   **Evidence:** `06-rpe.png`; `RPESheet.swift:92` distributes nine values across one row with a 36-point minimum height. The sheet exposes the countdown but no ±15 or Skip actions. `Hevy’s RPE reference` keeps rest controls and large increment/decrement controls available.  
   **Gym impact:** A tired thumb must aim precisely for half steps; adjusting a short rest requires dismissing the sheet.  
   **Smallest fix:** In `RPESheet.swift`, add 44-point ±0.5 buttons beside the selected value and compact rest adjustment/Skip actions. Keep the slider for broad changes.

5. **Major — Timed sets: no way to record per-set RPE.**  
   **Evidence:** `18-timed-set.png` has no RPE control for Plank. `Columns.swift:68` explicitly restricts RPE to rep-based measurements.  
   **Gym impact:** The owner’s “RPE per set” requirement cannot be met for holds or carries. This follows the current spec, so it is a requirement/spec mismatch rather than an accidental rendering bug.  
   **Smallest fix:** Add “Rate effort…” to `SetKindMenu.swift` for timed and distance sets, opening the existing `RPESheet`; show the recorded rating below the row without squeezing the time column.

6. **Minor — Accessibility: core logging information stops scaling at AX1.**  
   **Evidence:** `SetGrid.swift:63` and `RestBar.swift:103` cap Dynamic Type. `ValueCell` also permits text shrinking to 60%. This is code evidence, not a reproduced large-text screenshot.  
   **Gym impact:** Someone selecting larger accessibility sizes gets larger surrounding content while the crucial numbers remain constrained.  
   **Smallest fix:** In `SetGrid.swift`, add a stacked accessibility layout above AX1; in `RestBar.swift`, put the countdown and actions on separate rows. Preserve the compact layout at ordinary sizes.

7. **Minor — VoiceOver: load fields omit units and exercise context.**  
   **Evidence:** `SetRow.swift:202` supplies labels such as “Load, set 1” and values such as “suggested 105”. Column headings are accessibility-hidden in `SetGrid.swift`.  
   **Gym impact:** Repeated “set 1” controls are harder to identify, and kg versus lb is absent when inspecting an individual field.  
   **Smallest fix:** In `SetRow.swift`, include exercise name and units in the accessibility label/value; preserve the useful existing “suggested” and “required, empty” announcements.

8. **Minor — Rest bar and Live Activity: next-set instructions receive too little emphasis.**  
   **Evidence:** `04-rest.png` places a faint next-set line over visually busy scrolling content. `09-live-activity-card.png` renders the actual load/reps in grey while “Next” is brightly accented. `SessionLiveActivity.swift:254` explicitly applies secondary styling to those values.  
   **Gym impact:** The lifter can identify the timer more easily than what weight to prepare.  
   **Smallest fix:** In `RestBar.swift` and `SessionLiveActivity.swift`, promote next-set values to primary foreground and medium weight. Keep routine metadata secondary. Give the rest bar’s tappable next-set line a 44-point minimum height.

9. **Minor — Session statistics: “Sets” appears not to update after warm-ups.**  
   **Evidence:** `05-suggestion.png` shows two completed warm-ups but “Sets 0 of 14”. `SessionHeader.swift:39` labels the working-set count simply “Sets”.  
   **Gym impact:** Correct counting rules look like failed logging, especially to someone arriving from Hevy.  
   **Smallest fix:** Rename the statistic “Working sets” in `SessionHeader.swift`. Keep warm-ups excluded from working-set progress.

10. **Minor — Set-kind menu: advanced methods have no explanation.**  
    **Evidence:** `SetKindMenu.swift:19` presents method names without help. `Hevy’s set-type reference` includes explanation affordances.  
    **Gym impact:** “Myo-reps” versus “Myo-rep match”, generated segments, and locked follow-up rows require prior knowledge.  
    **Smallest fix:** Add an “About set types…” item in `SetKindMenu.swift` with brief descriptions of rest, generated rows, and stopping rules.

The **three highest-impact changes** are: make Start unobstructed, make suggested values readable at arm’s length, and make Finish accurately preview the saved workout.

Keep the **explicit superset bracket, A1/A2 labels, transition rest, and round rest**—they communicate the sequence better than Hevy’s supplied “Superset / Rest OFF” presentation. Keep the **plain-language suggestion reasons** and the **prominent timed-set Stop control**. The overall material separation is also sound: exercise cards remain opaque content, while navigation and the floating rest controls use glass. Preserve that restraint.

## What was done about it

Everything was fixed in geoah/rxtx.dev#113, together with bugs found running the app on
the simulator for the first time; an adversarial review then checked each fix. From the
PR's description:

From the Codex review:

- **Suggested values** looked disabled, and nearly vanished in dark mode. They are now a styled overlay with about 5:1 contrast in light mode and 6.5:1 in dark.
- **RPE sheet:** 44 pt ±0.5 steppers, and −15, +15 and Skip while a rest runs.
- **RPE on timed and distance sets** through "Rate effort…" in the set menu.
- **"About set types…"** help in the set menu.
- The header says "Working sets", so finished warm-ups don't look unlogged.
- **VoiceOver** fields name the exercise and the unit.
- At accessibility text sizes the rest bar's countdown and buttons go on two rows.
- The **Live Activity** shows the next set's values in primary text.
- The **e1RM chart** draws straight lines instead of a smoothed curve.

Found on the simulator:

- **Timed sets** showed a frozen orange "+0:00" as soon as Play was pressed. `TimelineView(.explicit([endsAt]))` draws its first frame with the date set to `endsAt`, so a fresh timer started in overtime. Now `.periodic(from: startedAt, by: 1)`: the row and the bottom pill count down from the suggested time ("1:03 left") and then count up in orange.
- **Routine preview:** Start routine sat under the floating tab bar. The tab bar now hides on the preview.
- **Session detail:** exercise cards had a chevron but didn't navigate. History's typed `[SessionID]` path refused the `ExerciseID`; it is now a `NavigationPath`.
- **Finish summary** ignored "Mark them done as shown": it showed 1 set and 1,050 kg while 14 sets and 6,973 kg were saved. The sheet and Save now share one projection, and the sheet says how many sets marking adds and how many can't be completed.
- **Rest bar:** its purple glass showed through sheets, and its "Next" line sat on the rows with nothing behind it. The bar now hides under sheets, and "Next" is its own glass capsule with the load in bold.
- Equipment no longer reads "None", and "Load steps: 5 kg from 0 kg" now reads "5 kg steps".
- The cable exercises (Pallof press, both pushdowns) step by 2.5 kg, not the 5 kg default; the Pallof press had been suggested 10 → 15 kg.

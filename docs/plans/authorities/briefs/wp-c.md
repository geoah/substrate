# Work package C: a token declares new packages only under its repository's authority (decision 0210)

Start from main: `git fetch && git switch -c feat/own-authority-packages origin/main`. Open the PR with base `main`.

Implement the rule in the plan's decision 5: **a token creates a new package only under the repository's own authority.** Any other authority comes from the binary: the seed, the boot upgrade, a catalog install. A sample import is unaffected because it rehomes onto the repository's authority. A package the repository already holds under another authority keeps working under the existing `source` rules; this rule is about creating one.

1. Find `authorizeNewPackage` in `internal/engine/seed.go`. Today it refuses only the publisher's own authority, by equality, and deliberately keeps "an `apply -f` of the files the binary ships" open. Close that door: a hand apply of a shipped provider or catalogue closure is refused, with a message that names `substratectl install <package>` and the catalog route. Read `isSubstratePath` and decide every hand: the owner's doors, an app's scoped apply under `declare:~/<package>` (its own authority, so admitted), an agent, a function. Apply the rule to every hand that is not the substrate's own.
2. Fix every test, fixture, e2e case, sample and doc snippet that declares a package under another authority through a token. Many tests use `example.com/...` in a repository named otherwise: prefer changing the fixture to the repository's own authority over adding exceptions. Check `internal/api/fake_test.go`, `internal/e2e`, `internal/providere2e`, `cmd/substratectl` tests, the console tests and `docs/`. You may not run the full suites: find the cases with `grep` and run each affected test by name.
3. Docs: wherever `docs/vocabulary.md`, `docs/bundles.md`, `docs/substratectl.md` or `AGENTS.md` say a token may declare any authority, or describe the `apply -f` door for shipped closures. Decision record **0210**, "A token declares new packages only under its repository's authority". Read decisions 0046, 0048 and 0109 first, and say which it amends.
4. This is a break. Title it `feat(vocabulary)!: declare new packages only under the repository's own authority`, and give a commit a `BREAKING CHANGE:` footer. Say what stops working: a token applying declarations under another authority, and `apply -f` of shipped provider files. Say what to do instead: `substratectl install` for providers and catalogues, and declaring your own kinds under the repository's authority. Say that packages already held are unaffected, and what a rollback does.

# Work package A: verified apps (decision 0209)

Your checkout starts at `feat/domains-record` (PR #1146). Create branch `feat/verified-apps` from it. Open the PR with base `feat/domains-record`.

Implement the plan's decision 3, decision 4's verified rule, the attribution section, an unverified app's `full`, and decision 8's development override, for the authorization flow.

1. **Client document.** `internal/authorize` reads an optional `substrate_authority` from the client document: a DNS-style authority (hold it to the authority grammar in `internal/vocabulary`); an invalid value is a claim refused, never a failed document.
2. **Authority document.** A type and a strict JSON parse: `authority`, `name`, `description`, `packages` (parse and keep the plan's shape, unused in phase 1), `apps` (`client_id`, `name`, `packages`, `apple.appIDs`). Fetch it from the record's `doc=` URL with `authorize.ConfinedClient()`, a 64 KB cap, a 10-minute cache of successes only, and the `sha256=` check when the record pins one. Its `authority` must equal the name looked up. Keep `internal/domains` free of an import of `internal/authorize` if `internal/authorize` imports `internal/domains`.
3. **Verification.** Wherever the server reads an authorization request (the authorize endpoint, the approval page, the set up check, the token exchange), an app is verified when: the `client_id` is https; its document claims authority A; `domains.Lookup(A)` finds a record with `doc=`; A's authority document lists the exact `client_id`; and the `redirect_uri` is https on host A or a name under A. Anything else is unverified, with a reason an owner can read. A loopback redirect or a loopback `client_id` is never verified. Inject the resolver (default `net.DefaultResolver`); tests use `domains.Static` and the fakes the existing authorize tests use for fetches.
4. **Development override.** `SUBSTRATE_INSECURE_AUTHORITY_DOCS`, a comma-separated list of `authority=path`, read in `internal/config`. The named authorities skip DNS and the fetch and read the file. Boot logs a warning naming each authority, and refuses to start when a file cannot be read. Pass it through `.mise/dev.sh` when set.
5. **Approval page** (`internal/api/authorize.go`'s view, `web/console/src/pages/authorize.tsx` and its components). Verified: the app's name, "by <authority>", and the authority document's `name`. Unverified: the claimed name marked unverified, where the access goes (the redirect origin, or "an app on this device" for loopback), and the claim that could not be confirmed, if any. An unverified app may still ask for `full`; the page says nothing confirms which program receives a token equal to the password. The Technical details switch shows the record, the document URL and whether the `client_id` is listed.
6. **Token and actor.** Store the verified authority on the token record (a new optional managed property on the core token kind, such as `appAuthority`; bump the kind's version). Derive the actor (`internal/api/auth.go`, `substrate.AppActor`): verified is `app:<authority>`; a loopback redirect or loopback `client_id` is `app:local`; anything else stays `app:<client_id host>`. Make `app:local` valid and reserved wherever actors are checked, and render it in the console. Package ownership under decision 0205 stays keyed on the client id: read `internal/substrate/packageowner.go`, `internal/engine/appagent.go` (decision 0207) and `internal/engine/seed.go`. The host-only legacy claim must keep comparing the client id's host, never the new actor. Add tests that a verified app's `declare:` apply and its approved agent still work.
7. **Docs.** `docs/apps.md`: publishing the TXT record and the authority document, and what verified and unverified mean on the page. `AGENTS.md`: the actor sentence (`app:<host>` becomes the three forms), and the `substrate.reamde.dev` placeholder paragraph (the name becomes a served domain that publishes an authority document; kind identity and the reserved character budget are unchanged). `docs/terms.md` gets "authority document". Decision record **0209**, "An app is verified by its authority's TXT record and document", amending 0194, 0195 (the actor) and 0204 (an unverified `full`).
8. **Tests.** A verification matrix in `internal/authorize`: listed, unlisted, no record, two records, malformed record, redirect off the authority, loopback, `sha256` mismatch, the document naming another authority, the development override. `internal/api` tests for the page view and the token's actor. Console vitests for the page states.

Suggested title: `feat(auth): verify an app's publisher through its domain's TXT record`.

# Plan: typed core declarations, host functions, and the console that follows

Status: design settled through review round 5 (three reviewers, adjudicated,
load-bearing claims verified against the code). This file is the working plan
for the three stacked PRs and is updated as work lands. It is a plan, not a
contract: the code that lands is the contract.

## The directives (owner)

1. Every core kind is strongly typed. No `definition: json` blob on kinds whose
   shape this project owns; no projected mirror properties regenerated on
   write. What the user writes is what gets stored. Admission may refuse a
   document or build runtime indexes from it; it must never rewrite the
   authored declaration into a different stored declaration.
2. The core kinds' YAML declarations are the single source of truth. Go (and
   TypeScript) type representations are generated from them (`kinds:gen`,
   with a `kinds:gen:check` no-drift check in CI), so the code and the
   declarations cannot drift.
3. OpenAPI/CRD compatibility where genuinely valuable, without losing domain
   datatypes.
4. Function input/output strongly typed; flat named arguments preferred over
   recursive schemas.

## Why (what the current design does wrong)

- A declaration record's authored content is only `properties.definition`;
  every other supplied property is silently ignored on write
  (`documentFromProps`), then regenerated by projection
  (`groupAgentDeclarations`). The console offers those projected properties
  as editable inputs, so what a person types is silently replaced. Verified
  empirically.
- `internal/vocabulary/types.go` states the rule this violates: "`json`
  survives only for payloads whose shape we do not own; anything a path reads
  must be declared." The loader reads every key of `definition`.
- The four agent built-ins (`query`, `propose`, `graphql`, `mutate`) are
  engine constants, not records: not browsable, not pickable, and the only
  hole in "an agent cannot name an unregistered tool".

## Verified show-stoppers the design is built around

- **M1: the boot upgrade cannot deliver a core-kind property change.** The
  projection writes rows through `t.put`, which validates against the
  still-stored OLD declaration (`write.go:111-127`,
  `vocabularywrite.go:613-618`); a refused row fails the open. Without a fix,
  shipping PR2's `runtime: host` records after PR1's typed enum bricks every
  upgrading repository. Fix: thread the candidate registry into the
  projection's type resolution (1a-prime below), with a test that adds a
  core-kind property and a row using it in one projection. This also retires
  the documented landmine at `kind.yaml:45-52`.
- **M2: the dialect rung cannot write through `t.put`.** At rung time the
  registry is empty (`engine.go:445,454`: promote runs before
  `loadStoredVocabulary`). The rung carries its own frozen dialect-1 decoder,
  builds and validates its own candidate registry with the generated
  dialect-2 decoders, and writes through the fold plus a changelog append per
  row. Never a direct `records` update.
- **Downgrade is silent loss, not clean failure**: an old binary skips rows
  without `definition` (`rowDocument`), opening a migrated store with every
  agent/function/bundle declaration quietly gone. The dialect stamp ships in
  the same transaction as the row rewrite, indivisibly.
- **M5: after the flip, registry structs are a read-only view.** The loader
  canonicalizes allowlists in place (`resolveFunction`); that mutation must
  never reach a row. Invariant tested: nothing encodes a registry-resident
  struct back to properties.

## Settled design (round 5, adjudicated)

### The dialect widening (minimal, no AST)

The full OpenAPI-style schema AST (recursion, named types, unions) is
rejected: the property dialect terminates by construction, every narrowing
guard is a single-level jsonb query with one array notch, and recursion would
force a general jsonb path walker into exactly the code where a regression
must not hide. Instead, three orthogonal flags plus one closure:

- **W1**: repeated scalar fields inside objects.
- **W2**: object-typed fields inside objects, to declared max depth 4
  (witnesses at 3: `kind.properties{}.transitions[].stamps{}` and
  `kind.properties{}.fields{}.values[]`).
- **W3**: `keyed: true`, the twin of `repeated: true`: a name-keyed map whose
  values follow the declared field set, with a declared key contract
  (`keyPattern`). This is what lets `kind.properties` stay a map in every
  authored document (the alternative rewrites the `properties:` block of
  every declaration in the tree) and lets bundle `inputs`/`modules` stay
  maps.
- **W4**: reference-typed fields inside objects, resolved and normalized
  (closes the half-admitted hole where a reference field parses but is never
  resolved).
- Two keyed levels in a row are refused (bites exactly one document:
  `trait.oneOf` becomes a repeated variant list). Still forbidden at every
  level: json/secret/digest/state/blobref as fields, named types, `$ref`,
  `oneOf`/`anyOf`/`allOf`, `additionalProperties`, `nullable`, `default`.

### References vs strings (split decision)

- **Reference-typed** (single-valued record pointers): `agent.provider`
  (to llmprovider), `tools[].callable`, `trigger.callable` (already is),
  `bundle.inputs{}.kind`, `mapping.from`/`to`. Gives schema-driven pickers.
- **Repeated strings + a `refersTo` marker** (kind/callable selectors):
  `agent.agents`, `emit`, `reads.kinds`, `function.call`, `bundle.installs`,
  `requires`. Reference-typing these would rewrite `emit: [person]` into a
  triple-nested identity object; `refersTo: kind|function|agent|authority|provider`
  is one loader-admitted key, changes no stored value, and is all the console
  needs for pickers. Existence validation already happens at registry
  finalization.

### Identity and managed properties

- `authority` stays authored (NOT id-derived: an actor row's id is the bare
  name, and three code paths plus two SQL readers need the property).
- `name` is DROPPED from properties. Nothing in SQL reads it; the real
  dependency is `displayTemplate: "{name}"` on eight core kinds. Fix: new
  derived template tokens `{localName}` and `{id}` (the `{snippet}`
  precedent), then the eight templates change in documents already bumping.
  Not spelled `{name}`: llmprovider has a real `name` property.
- `version` stays a declared managed property: stamped when absent (status
  quo), a supplied mismatch is REFUSED, never silently replaced. The
  "no version means upgrade me" property of the seed diff is preserved.
- A managed-property marker (beside `Implicit`) declares the engine-stamped
  set: `version`, `source`, quarantine fields, bundle lifecycle bools.
  Supplying one you may not write is refused, not ignored.

### Function IO goes flat (census-backed)

All 8 shipped function inputs are already flat scalar named arguments;
exactly one output nests (firecrawl websearch results, whose only consumer
is a post-hoc assertion). `input`/`output: json` are replaced by typed
`arguments`/`returns`: repeated objects of
`{name, type: string|int|float|bool|enum|json, repeated, required,
description, values}`. The engine RENDERS the LLM tool card from the list,
so it is valid JSON Schema by construction; enums arrive (today's dialect
has none, which is why setclass encodes an enum in prose); the latent
`type: any` invalid-schema bug dies; `CheckValue` collapses to one level.
`json` as an argument type is the named, greppable escape hatch. All four
host-function cards are expressible flat, verbatim.

### The meta-kinds ride the one rung

`kind`, `trait`, `propertytype`, `recordmapping` are typed in the same
atomic release, not later: a change to `core/kind` is only deliverable by a
rung (M1 makes the ordinary upgrade path unreachable for it), and a second
rung would mean a release where `kind` stores typed properties while `agent`
stores `definition`, the two-encodings state the no-coexistence rule forbids.
Inside the rung's transaction the meta-kind rows are translated and
validated FIRST into the rung's candidate registry; every other row
validates against that candidate. Typed meta-kind schemas: see the round-5
adjudication (keyed `properties`/`edges`/`fields`, repeated `transitions`,
`trait.oneOf` as a repeated variant list, `mapping.map` keyed with the
string arm dying).

### What honestly stays dynamic

Four leaves, all for the same reason (the value's type belongs to a kind
core does not own): `recordpatchrequest.diff` (admission validates it
against the target kind, which is stronger than any structural schema),
and the user-kind value leaves in `recordmerge.moved`,
`recordsplit.result`, `recordmergerequest.evidence` (containers typed).
Also typed away: `trigger.source` (discriminator + optional arms),
`run.effects` (keyed int), `llmmessage.toolCalls` (repeated object with the
arguments as the verbatim wire string).

### Codegen

- Generated from the 23 core kind documents: one Go struct per kind plus
  nested structs, enum constants with `Valid()`, admitted-key sets
  (replacing hand-kept `agentDataKeys` etc.), `Decode<Kind>` (structural
  validation; semantic checks stay hand-written), `Properties()` (the
  inverse, for the rung), and TypeScript for the console.
- Optional non-repeated scalars generate as POINTERS: absence stored is
  absence authored, and a materialized zero value is the likeliest silent
  round-trip bug.
- `state` is not a property (states live in their own column): generated as
  a separate accessor plus typed constants.
- Lives in leaf package `internal/corekinds` (zero substrate imports);
  generator is `cmd/kindsgen` with its OWN ~200-line dialect reader (the
  `cmd/vocabularydiff` precedent), so a broken generated file cannot make
  the generator unbuildable. A hand-written conformance test pins the two
  readers together: (1) generator reader and vocabulary loader agree on
  every core document; (2) per kind, generated key set equals declared
  property set both directions; (3) `Decode(Properties(x)) == x` per kind
  including absent-vs-empty.
- Tasks: `kinds:gen` (with `:go`/`:ts` narrowings) and `kinds:gen:check`
  wired into CI lint. Generated output is checked in.
- Where generation stops: core kinds are compile-time; runtime-declared user
  vocabulary stays `map[string]any` through the unchanged generic engine
  (coerceProps, fold, guards, GraphQL construction). Generated types stay
  out of `internal/substrate`. `KindInfo.Definition` survives as an API
  field with its provenance changed to "rendered from the parsed
  declaration", which decouples the console (PR3) from the flip (PR1).

### OpenAPI stance

Keep the domain dialect as the authored and stored form; add a generated
one-way OpenAPI 3.1 export (API description of core resources; the function
tool cards are OpenAPI-shaped by construction once IO is flat). Steal from
K8s structural schemas: every level typed, no recursion, closed objects, no
preserve-unknown-fields (our `json` is the honest escape hatch). Skip:
`$ref`, composition keywords, `additionalProperties`, `nullable`, `default`.

### Engine behavior fixes (round 3, unchanged)

- Empty `emit` legal (pure functions); trigger admission warns on discarded
  output; firecrawl's fake emit removed.
- `recordpatchrequest` diff validation moves into admission for every door.
- The agent `mutate` path carries the effective emit ceiling (today accept
  fails closed while reject succeeds; the LLM-judge loop closes with mutate
  alone). Confused-deputy tests.
- `host.propose` SDK sugar (lowers to the existing put effect).
- `runtime: host`: four core function records, browsable/pickable/callable
  by agents. Bare builtin names stay legal forever and canonicalize at parse
  both directions; grant checks fire for both spellings; host functions
  never reach the child-process runner (refusal at `runCallableRaw`, skips
  in prepare/warm/reconcile, `CallFunction` branch with query/graphql
  allowed under the token and propose/mutate refused, trigger admission
  refuses propose/mutate targets naming the rewrite); `ResolveFunction`
  excludes host functions from bare-name resolution; the Go card literals
  die as the schemas move into declarations.

## The three stacked PRs

- **PR1 (this branch): the typed core.**
  - 1a. Dialect foundation: W1, W2 (depth 4), W3 (`keyed`), W4, the
    `refersTo` marker, the managed-property marker, `{localName}`/`{id}`
    template tokens. Full accept/refuse matrix, coerce round-trips (jsonb
    float64 read-back), guard-query arms for keyed and nested,
    objects-stay-out-of-FTS preserved.
  - 1a-prime. The projection registry override (M1) plus its test. Before
    anything else touches the upgrade path.
  - 1b. Codegen: `cmd/kindsgen`, `internal/corekinds`, generated Go + TS,
    `kinds:gen`/`kinds:gen:check`, the three conformance tests. Lands before
    the flip so dialect 2 decodes through generated types from its first
    accepted row.
  - 1c. The atomic flip: typed declarations for all 23 core kinds (meta-kinds
    included), loader dialect changes with tombstoned old spellings (the
    `tools:` string arm, `capabilities:` wrapper, `input`/`output`,
    `trait.oneOf` map form, `mapping.map` string form), the `kinds/` sweep
    with version bumps, the rung per M2, `documentFromProps`/`rowDocument`
    rewired (supplying `definition` or a managed property is refused),
    mirrors and `groupAgentDeclarations` deleted, the GraphQL builder moved
    onto the parsed `Kind` (net deletion in `internal/gql/defs.go`),
    `KindInfo.Definition` re-provenanced.

### Where PR1 stands

1a, 1a-prime and 1b landed as described. 1c landed in three stages, and the
code is the contract for all of it:

- **A** — the loader gained the typed spellings beside the old ones.
- **B** — the core declarations, the `kinds/` sweep, typed declaration ROWS,
  the dialect rung, and the write path's refusals.
- **C** — the old spellings die. Each is refused naming its replacement (the
  `tools:` string arm, the `capabilities:` wrapper, `input`/`output`, the
  `trait.oneOf` map form, the `mapping.map` string form, and two the plan did
  not name: an index as a bare list, an OAuth feature's scopes as a bare
  list). The `definition` machinery is gone with them: the blob arms of
  `documentFromProps` and `rowDocument`, and a definition-bearing row is now a
  loud refusal on every path but the rung's. The rung carries a FROZEN copy of
  the dialect-1 grammar it needs (`engine/dialectonegrammar.go`), exercised
  only by the rung and pinned by old-shape fixtures per kind, so retiring a
  spelling from the loader can never move what a stored row translates to.

Two things the plan expected of 1c did not happen, and both are honest
deferrals rather than oversights:

- **The GraphQL builder still reads the declaration as a map.** The schema is
  built from `substrate.KindInfo` by two callers — the API's `/graphql` and the
  agent loop's built-ins — and `internal/api` may not import the engine, while
  `internal/substrate` cannot import `internal/vocabulary` (the vocabulary
  imports it). So the parsed `*vocabulary.Kind` is not reachable on the API
  path, and the net deletion in `internal/gql/defs.go` needs one of two moves
  first: `KindInfo` grows a typed structural projection, or schema building
  moves behind the `Dataset` contract. `kind.properties` is the meta-kind's one
  json leaf either way (a property declaration recurses), so the property walk
  survives both. PR3 decides it beside the console's typed reads; the file now
  says what it reads and why.
- **`Definition` stays on the parsed structs.** It is the authored data map —
  what the projection stores as the row's properties — and rendering it back
  from a parsed struct would materialize the loader's defaults, which is
  exactly the absent-vs-empty loss 1b's pointers exist to avoid. What died is
  the never-read `SourceYAML` on `Function`, `Bundle` and `Mapping`;
  `KindInfo.Definition` is re-provenanced in place, so the console is
  untouched.
- **PR2 (stacked): host functions and the engine fixes** (content above).
  Safe only because of 1a-prime. Its declaration edits are a second version
  bump on closures PR1 swept.
- **PR3 (stacked): the console.** Keyed/nested schema-driven editors,
  reference pickers including the repeated-reference fix (`controlFor`
  returns the single-reference control before checking `repeated`, so a
  repeated reference 422s today), tool/trigger arm selection,
  managed-property read-only badges, grant hints, generated TS replacing
  hand-written `types.ts`, the recordpatchrequest review inbox (pending
  card + before/after detail + accept/reject with `ifVersion`, cloned from
  the merge-request trio), and the SPA fix (missing assets 404, cache
  headers, one-time reload on `vite:preloadError`, regression test).

## Risks and the tests that hold them

- Critical: rung corruption at scale. Content-gated, idempotent,
  per-repository transactional; frozen V1 decoder in the rung's own code;
  old-shape fixtures per kind per transform; rebuild-equivalence test;
  interruption tests (before writes, mid-writes, before stamp).
- Critical: M1/M2 (above), each with its named test.
- Critical: downgrade refusal test (old binary against a stamped store).
- High: generator/loader drift. The conformance tests; `kinds:gen:check` in
  CI.
- High: absent-vs-empty round-trip loss. Pointers for optional scalars;
  conformance test 3.
- High: M5 (registry structs written back). Invariant test.
- Medium: the authored sweep misses a document. Loud loader refusals naming
  the replacement plus `kinds:check`.
- Medium: console breakage between PR1 and PR3. `KindInfo.Definition`
  re-provenanced rather than removed.
